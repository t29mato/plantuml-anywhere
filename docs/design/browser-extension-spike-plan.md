# Chrome拡張機能スパイク計画(未実施・司令塔承認待ち)

## 目的

VS Code拡張機能とは別スコープの成果物として、「ローカルの `.puml` ファイルを Chrome で
`file://` 直接開いたときに、その場でプレビュー表示する」単体のChrome拡張機能を作る
(2026-08-20 司令塔確認)。この価値提案が成立するかどうかは未検証であり、
Graphvizスパイクと同じ理由で、設計より先に単独スパイクで確認する必要がある。

## 確認すべき技術リスク(優先順)

1. **ブラウザが `.puml` ファイルを `file://` で開いたときに何が起きるか。**
   `.puml` はブラウザが認識するMIMEタイプ/拡張子ではないため、多くの場合は
   「ダウンロード」される(タブ内に表示されない)可能性がある。これが起きると
   content scriptが介入する余地がなく、この製品案自体が成立しない。**最優先で確認する。**
   - Chromeの実際の挙動は、OS側のファイル拡張子→MIMEタイプ関連付けやChromeのファイル
     タイプ判定ロジックに依存する可能性があり、実機で試す以外に確実な方法がない。
2. 1が「タブ内にプレーンテキストとして表示される」であれば、content scriptで
   `document.body` のテキストを読み取り、DOMを差し替えてSVGを描画できるかを確認する。
3. Manifest V3の `host_permissions` に `file:///*` を指定できるか、また
   ユーザーが `chrome://extensions` で「ファイルのURLへのアクセスを許可する」を
   手動で有効にする必要がある制約(Chromeの仕様上、拡張機能側だけでは自動化できない)を
   実機で確認し、UXへの影響としてドキュメント化する。
4. `@plantuml/core` のWASMレンダリングを、content script(ページの実行コンテキスト)内で
   実行できるか(拡張のCSP・ページ側のCSPいずれの制約も受ける可能性がある)。

## 判定基準

- テスト用の `.puml` ファイルをローカルディスクに置き、Chromeで `file:///path/to/test.puml`
  を直接開く
- 拡張機能なしの状態でこのURLを開いたときの挙動(ダウンロードされるか、テキスト表示されるか)を
  まず記録する
- 拡張機能ありの状態で、content scriptがページ内容にアクセスできるか、DOMを差し替えられるかを
  確認する
- 成立する場合: レンダリングまで一気通貫でSVG表示を確認する
- 成立しない場合(ダウンロードされてcontent scriptが介入できない等): 代替UX
  (例: 拡張機能のアイコンをクリック→ファイル選択ダイアログでプレビュー、等)を
  司令塔に提案し判断を仰ぐ

## ステータス

**実施済み。** 結果は `docs/design/browser-extension-spike-report.md` を参照。
判定: 成立する見込みが高い(要注意点1件: パック済み配布時のfile://アクセス許可の
